# 수집 출처 명세

이 문서는 Grant Radar KR이 자동 수집하는 범위와 확인 수준을 명시한다.
날짜와 건수는 변할 수 있으므로 실행 결과의 `data/run_manifest.json`을 최종 근거로 삼는다.

| 코드 | 출처 | 방식 | 인증 | 주요 필드 | 현재 상태 |
|---|---|---|---|---|---|
| `kstartup` | K-Startup 사업공고 | 공공데이터포털 공식 API | data.go.kr 서비스키 | 제목, 대상, 지역, 업력, 연령, 접수기간, 모집상태, 상세 URL | 2026-09-04 HTTP 200 확인 |
| `bizinfo` | 기업마당 지원사업 | 공공데이터포털 공식 API | data.go.kr 서비스키 | 제목, 분야, 대상, 기관, 접수기간, 해시태그, 상세 URL | 2026-09-04 HTTP 200 확인 |

## 수집 완료 상태

각 `fetch` 실행은 `data/run_manifest.json`에 원천별 최신 상태를 남긴다.

- `complete`: 1페이지부터 시작해 실제 고유 공고 수가 API의 전체 건수에 도달했거나
  빈 페이지까지 확인했다. 전체 건수가 제공되면 고유 공고 수가 그보다 적어서는 안 된다.
  수집 중 전체 건수가 바뀌거나 식별자 누락으로 저장하지 못한 공고가 있으면 완료로 보지 않는다.
- `partial`: 요청 범위는 정상 처리했지만 전체 소진을 확인하지 못했다. 중간 페이지부터
  시작한 실행, 페이지 한도 도달, 중복·누락·전체 건수 변동 등도 포함한다.
- `failed`: API 또는 정규화 오류로 중단됐다. 앞 페이지에서 저장한 데이터는 유지된다.

매니페스트에는 `start_page`, `last_page`(마지막 정상 응답 페이지, 응답 전 실패면 null),
`requested_pages`, `requested_per_page`, `pages_fetched`, `collected`, `reported_total`,
종료 이유와 오류를 기록한다. `collected`는 처리 항목 수로 중복·식별자 누락을 포함할 수 있다.
`range_complete`는 요청 범위 처리가 오류 없이 끝났다는 뜻이며, 끝 페이지를 먼저 만나
조기 종료한 경우도 true다. 전체 수집 여부는 `status`로 판단한다.
인증키, 회사 정보, 검색어와 공고 본문은 기록하지 않는다. 기존 스키마 1 파일도 읽으며
새 범위 필드는 해당 원천의 다음 실행부터 채워진다.

CLI는 `partial`에도 종료 코드 0을 반환하지만 부분 수집 경고를 출력한다.
주간 스크립트는 이 경고를 로그와 메일에 표시한다. 부분 수집을 포함한 선택 범위 보고가
성공하면 `last_success`를 갱신한다. 매니페스트가 없거나 해석되지 않으면 실패로 처리한다.
`complete`도 수집 중 원천이 변하지 않은 단일 스냅샷이나 전국 모든 공고의 포함을 보장하지 않는다.

## 범위의 한계

- 두 API가 모든 정부·지자체 지원사업을 포함한다고 가정하지 않는다.
- `partial` 실행 결과로 공고의 소멸이나 전체 부재를 단정하지 않는다.
- 동일 공고가 두 원천에 중복 게시될 수 있으며 현재는 원천별 별도 레코드로 보존한다.
- 상세 자격과 첨부파일 내용은 수집 범위 밖이며 원문에서 확인해야 한다.
